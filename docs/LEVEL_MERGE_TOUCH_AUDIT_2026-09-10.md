## Перевірені результати

1. Об’єднання відбувається окремо для таймфрейму і сторони HIGH/LOW.
   Runtime викликає `build_reference_levels` окремо для кожного TF.
   У межах TF близькі виявлені екстремуми об’єднуються, їх `touches` сумуються.
2. `touches` зараз означає кількість виявлених pivot-кандидатів у групі,
   а не всі окремі повернення ціни до зони. Кожний pivot починається з 1.
3. Вимога унікальності максимуму/мінімуму у вікні з 40 свічок відкидає
   близькі в часі рівні вершини. Дві однакові вершини на індексах 40 і 50
   дають нуль HIGH-рівнів; на індексах 40 і 80 — кластер із двома дотиками.
   Якщо друга вершина на індексі 50 трохи нижча, результат — один дотик.
   Це обмеження нашої `unique_centered_40` гіпотези; документація не дає
   підстав стверджувати, що алгоритм Digash має те саме обмеження.
4. Повторний розрахунок тих самих свічок із persisted levels не збільшує
   touches. Дублікати свічок із тим самим часом відкриття нормалізуються.
5. Для зони HIGH з вершинами 110.1 на індексі 40 і 110 на індексі 80
   отримуємо price=110, origin=40. Отже, лінія нижньої межі зони може починатися
   на свічці іншої вершини. Для віку зони це осмислено, але для променя,
   який має починатися саме з вершини за ціною лінії, потрібен окремий anchor.
6. Canonical Digash catalogue включає активні одиночні екстремуми нарівні
   з кластерами. `min_cluster_touches=2` не фільтрує Digash-гілку каталогу.
   Графік бере 8 найближчих рівнів за абсолютною відстанню, без пріоритету
   повторних дотиків і без групування однакової ціни між TF.

## Відтворення

Із кореня репозиторію, без записів у БД:

```python
from sniper_paper.market import Bar
from sniper_paper.shadow_levels import build_reference_levels
from sniper_paper.levels import LevelSide

for peaks in ({40: 110, 80: 110}, {40: 110, 50: 110},
              {40: 110, 50: 109.95}, {40: 110.1, 80: 110}):
    bars = [Bar('XUSDT', 60000, i*60000, (i+1)*60000,
                100, peaks.get(i, 101), 99, 100, 1, 0, 1)
            for i in range(120)]
    result = build_reference_levels(bars, timeframe='1m',
                                    now_ms=7200000, tick_size=0.01)
    print([(x.price, x.touches, x.origin_at_ms//60000)
           for x in result.levels
           if x.side is LevelSide.HIGH and x.broken_at_ms is None])
```

Результати: `[(110, 2, 40)]`, `[]`, `[(110, 1, 40)]`, `[(110, 2, 40)]`.

`test_level_runtime_revision.py`. Вони не доводять точність відтворення Digash:
тест повторних дотиків використовує вершини через 40 свічок.

## Реалізоване виправлення

Реалізацію оформлено у версії
`digash_horizontal_levels_v3_touch_episodes`. Touches тепер є окремими
causal return episodes із seed timestamp, departure/tolerance гіпотезами та
обрізанням на першому break. Розділені плато й рівні з однаковою ціною у
різних TF для відображення; торговий каталог та ID між TF не змінюються.

- Seed екстремуму відділений від подій повторного дотику: повернення більше не
  мусить бути новим унікальним 40-свічковим екстремумом.
- Суміжне плато рахується однією подією; новий touch виникає лише після виходу
  із розширеної зони й повернення. Це наша версіонована гіпотеза, а не
  опублікована математика Digash.
- Один touch зберігається як `digash_extreme`, повторні — як `digash_cluster`;
  глобальної заборони одиночних рівнів не додано.
- Історичний `origin_at_ms` відділений від `ray_anchor_at_ms` для графіка.
- Однакова ціна на різних TF групується лише у візуальному представленні:
  торгові ID та лічильники touch не об'єднуються.
- Регресійні тести покривають повторний replay, плато, близькі повернення,
  causal break, HIGH/LOW симетрію та стабільність ID/provenance.

## Що залишається гіпотезою

Невідомими лишаються точна форма pivot, числова умова відходу між touch-подіями,
проміжні допуски між 1m і 1d та право одиночного рівня брати участь у конкретному
торговому сетапі. Їх не можна називати точним відтворенням Digash без нових
матеріалів або еталонної вибірки зі сканера.

Автоматичне збільшення merge tolerance або відключення молодших TF ці
проблеми не вирішує. Проміжні допуски TF вже є нашою інтерполяційною гіпотезою.
